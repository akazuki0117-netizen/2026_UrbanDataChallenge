# ペルソナ・ユースケースの整理（persona-usecase）

機能や画面に先に固執すると本質が見えなくなる。**ペルソナ → 場面 → ユースケース → 機能・情報ごとの「なぜ必要か」→ 画面** の順で組み立てる。


## 手順

### 0. 前提（分かっていること／分かっていないこと）

- 数字は分析・統計から取り、**出典を必ず添える**（例：高齢化率、入込観光客数、分析の結果）
- 人物像（スマホの使い方、知識、行動）は**仮定**としてはっきり分ける。確かめていないものは「確かめること」に回す

### 1. ペルソナ

- **主役を1人に決める**。主役ではない人は「別の弱さを持つ人」「主役を気にかける人」などとして、多くても2〜3人
- 項目をそろえた表で書く：

| 項目 | 書くこと |
|---|---|
| 人物 | 年齢・住まい・暮らし（1〜2文） |
| 体・能力 | 歩ける距離、視力・聴力など、操作や行動に効くもの |
| スマホ・道具 | 何を持っていて、どこまで使えるか |
| 知識 | そのテーマについて何を知っていて、何を思い込んでいるか |
| 情報の入り方 | ふだん・いざというとき、何から情報を得るか |
| 困りごと | 具体的に（「選択肢が多いと止まる」「スクロールが苦手」など） |
| ゴール | 1文で太字 |
| アプリに求めること | ゴールから逆算して1〜2文 |

- 主役を選んだ理由を、分析の数字と結びつけて1段落書く
- **ある人のための機能が、別の人（主役）の行動を妨げないか**を「注意」として書く（例：家族の安否を知りたい人が電話をかけると、本人の避難が遅れる）

### 2. 場面

- 同じ人でも場面で必要なものが変わる。時間の流れで3〜5個に分ける（例：平時／直後／移動中／着いた・止まった／例外の場面）
- 場面 × ペルソナの表で、それぞれの状態を1行ずつ

### 3. ユースケース

- **「誰が・どんな状況で → 何をする → アプリが何を返す → うまくいった状態」**の形で書く
- ID を振る（`UC-<ペルソナ><番号>`。例：`UC-A3`）。いちばん大事なものに ★
- いまの実装でできるかを **○ できる／△ 一部／✕ できない** で添え、△✕ には理由を短く

### 4. 機能・情報ごとの「なぜ必要か」

- いまある（または案にある）機能・情報を1行ずつ並べ、**当たるユースケース**と**なぜ必要か**を書く
- 判定を付ける：**残す／平時へ移す・その場面では隠す／削る候補／要検討**
- **どのユースケースにも当たらないものは、削る候補**。「数えると、これとこれを外せば〇〇が実現する」のように、効果を1文で言う

### 5. 画面への示唆

- いちばん大事なユースケース（★）から逆算して、その画面に**スクロールなしで**載せるものだけを描く（テキストのモック可）
- 声・音など、画面を見ない場合の出し方も書く
- 消したもの・残したもの・まだ決めていないことを分けて書く

### 6. 決めること・確かめること

- 次の打ち合わせで決めること（番号つき）
- ペルソナの仮定で、確かめること
- 市・関係者に聞ける場があれば、そこで聞く質問の候補

## 出力

- **Markdown**：上の0〜6章をそのまま見出しにする
- **Figma に貼るボード（求められたら）**：固定幅（2400px）の HTML。外部フォント・JS なし（html.to.design などで取り込めるように）。章ごとに白いフレーム、ペルソナは色分けのカード、ユースケースは「ペルソナの行 × 場面の列」の付箋、機能は判定の色で塗ったカード。ヘッドレス Chrome で全体を PNG にも書き出す（Figma にそのままドラッグできる）
- 作業中のたたき台をリポジトリに上げたくないときは、git に載らない場所（`.git/info/exclude` に足したフォルダなど）に置く

## チェック

- 主役が1人に決まっているか
- 機能の表に、ユースケースに当たらないものが残っていないか（あれば削る候補になっているか）
- 数字に出典があり、仮定と混ざっていないか
- 「我々が使える」ではなく「ペルソナが使える」根拠になっているか
