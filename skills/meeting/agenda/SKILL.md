# アジェンダ・進行表（agenda）

決めることがある会議の前に作る、1枚の HTML。旧リポジトリの「空き家アプリ レビュー会（9/30）」「防災アプリ レビュー会（10/2）」で使った形式。見本は [`examples/`](examples/)。

## 置き場所

- その会議のフォルダ（`meeting/<YYYYMMDD>_<会議名>/`）に `アジェンダ・進行表.html` として置く。会議の後、同じフォルダに議事録の README を書く（[`../gijiroku/`](../gijiroku/SKILL.md)）
- 1ファイルで完結させる（外部の JS なし。フォントは Google Fonts の BIZ UDPGothic だけ）

## ページの構成（上から順に）

| 部品 | 中身 |
|---|---|
| **見出しと meta** | 会議名、日付（曜日）、時間（例：60分）、対象（チーム・メンバー）、判定の基準（例：課題選定表の評価軸） |
| **今日のゴール**（色つきの1枚） | この会議で何を決めるか、2〜3文 |
| **前提** | 判定の土台になる表や数字（例：課題選定表のその行）と、今日どう見るかの説明 |
| **進行（タイムライン）** | 時刻と所要分の枠を並べる。決める議題の枠は強調（★）し、「決めること：」を青字で書く。根拠の数字は灰色の小さい文字で添える |
| **判定シート**（入力フォーム） | 選定表の列ごとに「選定時の値／今日の判定（選択）／根拠／次の手」、決めることごとに「結論（選択）／理由・条件／担当・期限」、今日の結論（ひとこと）、記入者 |
| **補助の観点**（時間があれば） | 定量的な根拠、仮データの見せ方、行政批判のリスクなど |
| **レビュアーの見立て**（叩き台） | 作る側の見立てを先に出しておく（会議で崩す前提） |
| **事前に用意するもの** | 動くアプリの起動方法、資料のパス |

## 時間割の作り方

- 合計をちょうど会議時間にする（例：60分＝前提5／デモ10〜12／★議題8〜20 ×1〜2／その他10／判定と次の手5）
- **最初に前提共有、最後に判定と宿題**を必ず置く
- 決めることは2つまでを★にする。残りは「そのほかの判断（短く）」にまとめる
- 課題リストの ID（例：F6・G1）を議題の横にタグで付けておくと、議事録・課題リストとつなげやすい

## 判定シートの作り（必須の動き）

- 入力すると **localStorage に自動保存**（キーは会議ごとに変える。例：`bousai-review-20261002`）。読めない環境でも落ちないよう try/catch
- **「議事録用にコピー」**：Markdown の表に整形してクリップボードへ。`file://` で権限が無いときは、選択状態のテキスト欄を出して Ctrl+C を促す
- **「ファイルに保存（.md）」**：同じ Markdown をダウンロード
- **「入力を消す」**：確認ダイアログのあとで消す
- 行（列・決めること）は JS の配列で持ち、表は配列から描く（行の追加・変更を1か所で済ませる）

## 見た目の約束

- ライト／ダークの両方に対応（`:root` に色の変数、`prefers-color-scheme: dark` で切り替え）
- スマホ幅（600px 以下）では時間の列を上に積む
- 印刷時は枠が途中で切れないようにする（`break-inside: avoid`）

## 作ったあと

- ブラウザで開き、判定シートに入力 → 再読み込みしても残る、コピーした Markdown が議事録にそのまま貼れることを確かめる
- 会議のあと、コピーした判定シートの Markdown を議事録の「決定事項」「宿題」に反映する
