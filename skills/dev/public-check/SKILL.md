# push 前の公開チェック（public-check）

このリポジトリは public。ルールは [`docs/公開のルール.md`](../../../docs/公開のルール.md)。
**push の前に毎回このチェックを通す。** 1つでも引っかかったら push しない。

## 手順

1. チェックのスクリプトを走らせる（リポジトリのいちばん上で）

   ```bash
   python skills/dev/public-check/scripts/check_public.py
   ```

   - 何も指定しないと、**これから push するコミットで変わったファイル**と、**まだコミットしていない変更**を調べる
   - 全ファイルを調べるとき：`python skills/dev/public-check/scripts/check_public.py --all`
   - コミットの作者のメールアドレスも調べる（noreply 以外なら止める）

2. 結果を読む
   - `NG` が出たら、その行を直してからもう一度走らせる。直し方は下の表
   - `要確認` は機械では決められないもの（例：人の名前らしき語）。中身を見て、問題なければそのままでよい
   - `OK` だけなら push してよい

3. スクリプトでは見つけられないものを、**自分の目で**確かめる（下の「目で見ること」）

4. 報告する：何を調べたか、引っかかったもの、どう直したか

## スクリプトが見るもの

| 種類 | 見つけるもの | 直し方 |
|---|---|---|
| メールアドレス | 「名前＠ドメイン」の形（コンテスト事務局・noreply などの決まったものは除く） | 消す。メンバーは GitHub のユーザー名で書く |
| 電話番号 | 「0から始まり、ハイフンで3つに区切った数字」の形 | 消す |
| 秘密の値 | API キー・トークンの形（`sk-`、`AKIA`、`ghp_`、`github_pat_`、`AIza`、`xox`、`-----BEGIN ... PRIVATE KEY-----` など）、`password=`・`api_key=`・`secret=` に値が入っている行 | 消して `.env` に移す。**push してしまったキーは、発行元で無効にしてから作り直す** |
| 入れてはいけないファイル | `.env`、`.env.*`（`.env.example` は可）、`*.pem`、`*.key`、`credentials*.json` | コミットから外し、`.gitignore` に入れる |
| **実名（自分で登録した語）** | `.private-words.txt` に書いた語（メンバーの実名・本当のメールアドレスなど） | GitHub のユーザー名に置き換える |
| コミットの作者 | push するコミットの作者のメールアドレスが noreply か | `git config user.email` を noreply にする。作り直しは `git commit --amend --reset-author`（push 前のものだけ） |

### `.private-words.txt`（実名のリスト）

実名をリポジトリに書くわけにはいかないので、**実名のリストは各自の手元にだけ置く**。

- リポジトリのいちばん上に `.private-words.txt` を作り、1行に1語ずつ、見つけたい語（メンバーの名字・本当のメールアドレスなど）を書く
- このファイルは `.gitignore` に入っていて、push されない
- `#` で始まる行はコメント

## 目で見ること（スクリプトでは分からない）

- **画像・PDF・スライド**の中の名前・顔写真・連絡先（PDF は文書のプロパティの「作成者」も）
- 議事録の中の、個人の事情（資格試験・本業の仕事の中身・家族・健康）や会社の内部情報
- 会議の録画・自動メモの原本を、そのまま貼っていないか
- 再配布が許されていないデータの本体を入れていないか（出典の URL だけにする）

## push を止めるしくみ（任意）

毎回のチェックを忘れないように、push の前に自動で走らせることもできる。

```bash
git config core.hooksPath .githooks
```

これで `.githooks/pre-push` が push のたびに `check_public.py` を走らせ、NG があれば push を止める。
