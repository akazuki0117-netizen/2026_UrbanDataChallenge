# 2026_UrbanDataChallenge — アーバンデータチャレンジ2026

チーム開発リポジトリ。オープンデータを使って地域の課題を解く作品のコンテスト「[アーバンデータチャレンジ2026](https://urbandata-challenge.jp/udc2026_entry)」（UDC2026）向け。

**作品のタイプ：アプリケーション／作品のテーマ：教育・政治**
概要・日程・審査基準は [`docs/contest.md`](docs/contest.md)。

---

## 作っているもの：Politica（ポリティカ）

**未成年の、選挙権をまだ持たない人をターゲットにして、政治への参画を目指すアプリケーションを作る。**

11/14 の事前キックオフで、次のように決めた（[議事録](meeting/20261114_事前キックオフ/README.md)）。

- 既存のプロダクト「ひそひそ」の枠組みを変え、選挙権のない若い世代向けの**政治教育・仮想投票のプラットフォーム**として作り直す
- 利用の入口で「18歳以下か」をたずね、未成年が対象であることを担保する
- ホスティングは Cloudflare
- 中身（機能）は、各自のアイデア（[`idea/`](idea/README.md)）を持ち寄って 11/21 の会議で決める

## 前回のハッカソンから持ってくること

11/20 の振り返り会のまとめは [`docs/引継ぎ_前回のハッカソンから.md`](docs/引継ぎ_前回のハッカソンから.md)。いちばん大事な3つ：

1. **アイデアを出す前に、目的・ターゲット・出したい効果を決める**（どんな場面で、何が変わったら成功か）
2. **要件定義に期間の半分を使ってもいい。技術要件（ディレクトリ・Cloudflare の構成・API・JSON の形）は最初に詰める**
3. **開発は画面ごとではなく、フロントとバックエンドで分ける**。開発・テスト・ログを見られる環境を最初に整える

## 📁 ディレクトリ構成

```
2026_UrbanDataChallenge/
├─ README.md     ← いまここ
├─ docs/         資料（contest.md＝コンテストの概要、前回からの引継ぎ、アピール資料）
├─ meeting/      🗒 会議（1会議＝1フォルダ `YYYYMMDD_会議名/`。議事録・アジェンダ・質問案）
├─ idea/         💡 アイデア置き場（メンバーごとのフォルダ。1案＝1フォルダ）
├─ analysis/     📊 定量分析（メンバーごとのサブフォルダ）
├─ survey/       🔍 一次資料・既存サービスの調査（主権者教育・若者の政治参加など）
├─ app/          🛠 本実装
│  ├─ src/           ソースコード
│  ├─ design-drafts/ 設計書
│  ├─ planning/      バックログ・バーンダウン・ガントチャート
│  └─ ui-import/     デザインのモック
└─ skills/       🧰 チームのスキル（design／dev／analysis／research／meeting／product／review／presentation）
```

- **このリポジトリは public。** 実名・連絡先・API キーなどは載せない。push の前に [`skills/dev/public-check/`](skills/dev/public-check/SKILL.md) のチェックを通す（ルールは [`docs/公開のルール.md`](docs/公開のルール.md)）
- ブランチ：開発は `develop`、提出する版と資料は `main`
- 使うオープンデータは、データ提供者の利用規約を確かめてから入れる。出典（URL・取得日）を必ず残す
