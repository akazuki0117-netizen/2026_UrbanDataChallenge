# 政治タイプ診断アプリ（仮）仕様

ラベル: `ready-for-agent`

## Problem Statement

未成年（主に投票権を持つ前の中高生）は、政治を「難しい」「自分には関係ない」と感じており、各政党が何をしようとしているのかを知るきっかけがない。既存の投票マッチングサービスは選挙前に大人が使うことを想定しており、設問も結果も硬く、未成年が気軽に触れて「政治って意外と自分ごとだ」と感じられる入口になっていない。その結果、18歳になっても政治への関心やリテラシーが育たないまま、投票に行かない層が生まれている。

## Solution

LINE風のトーク画面で、同い年の友達のような優しいAIキャラと会話しながら、身近な論点について自分の考えを答えていくスマホWebアプリ。ボタンで答えても、自由な言葉で答えてもよい。会話が終わると「あなたは〇〇党タイプ」という結果と、全政党とのマッチ率（論点別の内訳つき）が表示される。各政党については「何をしたい？」「何が変わる？」を同じ形式で解説し、公約の出典や公式動画にもすぐ飛べる。結果を見た後は、AIキャラに「この政党が勝ったら私の生活はどう変わる？」と自由に質問できる。最後に、何歳から投票できるか、次の選挙はいつかを案内する。全政党を同じ扱いで見せ、特定の政党を勧めないことで中立性を保つ。ログインは不要で、回答は保存しない。

## User Stories

### 入口・はじめ方

1. 未成年のユーザーとして、URLを開くだけでログインなしに始めたい。そうすれば気軽に試せる
2. 未成年のユーザーとして、最初に「5分くらいで終わる」とわかりたい。そうすれば途中でやめずに済む
3. 未成年のユーザーとして、回答がどこにも保存されないことを最初に知りたい。そうすれば安心して本音で答えられる
4. 未成年のユーザーとして、スマホのブラウザで普段のチャットアプリと同じ感覚で操作したい。そうすれば使い方を覚えなくて済む
5. ハッカソンの審査員として、URLを開いてすぐ体験全体を試したい。そうすれば短時間で評価できる

### 会話（設問）

6. 未成年のユーザーとして、AIキャラから友達のようなタメ口でメッセージが届いてほしい。そうすれば政治の話でも身構えずに済む
7. 未成年のユーザーとして、メッセージが1つずつ届く演出を見たい。そうすれば本当にトークしている感覚になれる
8. 未成年のユーザーとして、返信の候補をボタンから選んで答えたい。そうすれば言葉にしにくい考えでも答えられる
9. 未成年のユーザーとして、自分の言葉で自由に返信したい。そうすれば選択肢にない微妙な考えも伝えられる
10. 未成年のユーザーとして、「わかんない」「どっちでもいい」と答えても責められずに次へ進みたい。そうすれば知らない論点でも最後まで続けられる
11. 未成年のユーザーとして、どんな答えにもキャラが「その考え方もあるよね」と肯定的に返してほしい。そうすれば間違いを恐れずに答えられる
12. 未成年のユーザーとして、キャラが自分の政治的な意見を言わないでほしい。そうすれば誘導されていると感じずに済む
13. 未成年のユーザーとして、教育・バイト・SNSなど身近な論点が含まれていてほしい。そうすれば政治が自分の生活とつながっていると感じられる
14. 未成年のユーザーとして、各設問の前に論点が一言でわかる短い説明がほしい。そうすれば知らない言葉があっても答えられる
15. 未成年のユーザーとして、今どこまで進んだかがわかりたい。そうすれば残りの量が見えて続けやすい
16. 未成年のユーザーとして、全15問・10論点で終わってほしい。そうすれば5分以内に結果までたどり着ける

### 自由回答の解釈

17. 未成年のユーザーとして、曖昧な言い方で答えても、AIがその意図を汲んで賛成〜反対の5段階に変換してほしい。そうすればボタンを選ばなくても答えになる
18. 未成年のユーザーとして、AIが判断できない答えは「どちらでもない」として扱われ、会話のテンポが止まらないでほしい。そうすればストレスなく進められる
19. 未成年のユーザーとして、結果画面で「AIがあなたの答えをこう解釈しました」という一覧を見たい。そうすれば誤解されていないか確かめられる
20. 未成年のユーザーとして、解釈一覧から自分の回答を修正し、結果を再計算したい。そうすれば納得できる結果になる

### 結果

21. 未成年のユーザーとして、「あなたは〇〇党タイプ」という結果を見たい。そうすればMBTIのように自分のタイプとして楽しめる
22. 未成年のユーザーとして、一番近い政党だけでなく全政党とのマッチ率を見たい。そうすれば「完全に一致する政党はない」ことに気づける
23. 未成年のユーザーとして、論点ごとに「この点は〇〇党と近く、××党とは遠い」という内訳を見たい。そうすれば政党同士の違いがわかる
24. 未成年のユーザーとして、マッチ率の計算方法を見たい。そうすれば結果が恣意的でないと納得できる
25. 未成年のユーザーとして、政党データが「〇年〇月時点の公約」に基づくと知りたい。そうすれば情報の鮮度がわかる
26. 未成年のユーザーとして、もう一度最初から診断をやり直したい。そうすれば違う答えで結果を比べられる

### 政党の解説・出典・動画

27. 未成年のユーザーとして、各政党が「何をしたい？」を短く知りたい。そうすれば公約を全部読まなくても要点がわかる
28. 未成年のユーザーとして、各政党の政策で「何が変わる？」を自分の生活に引きつけて知りたい。そうすれば政策を自分ごととして考えられる
29. 未成年のユーザーとして、全政党の解説が同じ項目・同じくらいの長さであってほしい。そうすれば公平に比べられる
30. 未成年のユーザーとして、解説や立場の根拠となった公約の出典に飛びたい。そうすれば自分で一次情報を確かめられる
31. 未成年のユーザーとして、各政党の公式YouTube動画をアプリ内で見たい。そうすれば文字だけでなく雰囲気もつかめる
32. 未成年のユーザーとして、自分と遠い政党の解説も同じように見たい。そうすれば違う考え方にも触れられる

### 結果後のAI対話

33. 未成年のユーザーとして、結果を見た後にAIキャラへ自由に質問したい。そうすれば疑問をその場で解消できる
34. 未成年のユーザーとして、「〇〇党が勝ったら私の生活はどう変わる？」と聞いて答えてほしい。そうすれば政策の影響を具体的にイメージできる
35. 未成年のユーザーとして、AIの答えが事前に用意された公約データと解説だけに基づいていてほしい。そうすれば根拠のない情報を信じずに済む
36. 未成年のユーザーとして、AIの答えに出典がついていてほしい。そうすれば自分で確かめられる
37. 未成年のユーザーとして、「どこに投票すべき？」と聞いても特定の政党を勧められないでほしい。そうすれば自分で考えて決められる
38. 未成年のユーザーとして、データにないことを聞いたら「わからない」と正直に言ってほしい。そうすればAIの作り話に惑わされない
39. 未成年のユーザーとして、AI対話でもキャラが同じ優しい友達の口調であってほしい。そうすれば体験が一貫する

### 投票への橋渡し

40. 未成年のユーザーとして、自分が何歳になったら投票できるかを知りたい。そうすれば投票を将来の自分ごとと感じられる
41. 未成年のユーザーとして、次の国政選挙がいつかを知りたい。そうすれば政治のニュースに目を向けるきっかけになる
42. 未成年のユーザーとして、選挙の仕組みを短く解説してほしい。そうすれば投票の流れがイメージできる

### シェア

43. 未成年のユーザーとして、論点ごとの自分のスタンスを画像でシェアしたい。そうすれば友達と考えを比べて話題にできる
44. 未成年のユーザーとして、シェア画像に政党名やマッチ率が入らないでほしい。そうすれば選挙期間中でも公職選挙法上の心配をせずにシェアできる

### 中立性・プライバシー

45. 保護者・教員として、アプリが特定の政党を勧めないことを確認したい。そうすれば子どもや授業で使わせられる
46. 保護者・教員として、回答がサーバーに保存されないことを確認したい。そうすれば未成年の信条（要配慮個人情報）が漏れる心配がない
47. 保護者・教員として、対象政党の選定基準を見たい。そうすれば「なぜこの党が入っていないのか」に説明がつく
48. 保護者・教員として、全政党が同じ形式・同じ量で扱われていることを確認したい。そうすれば公平性を信頼できる

### 運営（チーム）

49. データ担当として、政党・論点・立場・出典・解説・動画をJSONで管理したい。そうすればDBなしで更新できる
50. データ担当として、データがルール（全政党×全論点、出典必須、解説の項目・長さ、動画本数）を満たしているか自動で検査したい。そうすれば偏りや抜けを公開前に防げる
51. データ担当として、AIで下書きした解説を人がチェックしてから載せたい。そうすればAIの誤りや偏りを防げる
52. 開発者として、モック段階ではJev・LLM・政党データをダミーに差し替えて体験全体を動かしたい。そうすればAPIの準備を待たずに画面と会話の流れを完成できる
53. 開発者として、本実装でダミーを本物のJev・LLM・データに差し替えたい。そうすれば画面側のコードを変えずに中身だけ置き換えられる
54. 開発者として、本実装の段階でJevの日本語精度を確かめ、足りなければ自由回答の解釈をLLMに切り替えたい。そうすれば精度の問題があっても体験を壊さずに済む

## Implementation Decisions

### 前提

- ハッカソン提出作品。5人・1ヶ月
- スマホブラウザで動くWebアプリ。アプリストアには出さない
- 技術は未定。推奨構成は、画面をNext.js（Vercelで公開）、自由回答の解釈をTypeSafe Jev、結果後の対話をLLM（Claude等）、データをリポジトリ内のJSONとする構成
- ログインなし。回答はサーバーに保存せず、端末内（ブラウザのメモリ）で処理する。DBは使わない
- サーバー側の処理は「自由回答の解釈」と「結果後のAI対話」の2つのAPIだけ

### 進め方（2段階）

- **モック段階（1週目）**：LINE風の画面と会話の流れを完成させる。自由回答の解釈・AI対話・政党データは、決まった値を返すダミーにする
- **本実装段階（2週目以降）**：ダミーを本物のJev・LLM・政党データに差し替える。Jevの日本語精度はこの段階で確かめ、不足すれば自由回答の解釈をLLMに切り替える
- 政党データ作りは1週目から並行して進める（最も時間がかかり、最も重要な作業）

### モジュール

1. **診断セッション**（メインのモジュール）
   - 設問セットと「回答解釈器」を受け取って会話を進める状態機械
   - 入力：ユーザーのメッセージ（選んだボタン、または自由入力のテキスト）
   - 出力：キャラの次のメッセージ（返信候補ボタン、進捗を含む）、または最終結果
   - 最終結果：一番近い政党（〇〇党タイプ）、全政党のマッチ率、論点別の内訳、AIの解釈一覧
   - 解釈一覧から回答を修正すると結果を再計算する
   - マッチ率の計算はこのモジュールの内部に持つ
2. **回答解釈器**（差し替え可能なインターフェース）
   - 入力：設問と自由入力のテキスト
   - 出力：5段階のスタンス、または「判断不能」
   - 実装は3つ：ダミー（モック段階）、Jev、LLM（Jevの精度が足りない場合の代替）
   - 判断不能のとき、診断セッションは「どちらでもない」として扱い、確認を挟まずに次へ進む
3. **政党データ**（JSON）
   - 論点（10個）と設問（15問）、各論点の短い説明
   - 政党（国会に議席があり政党要件を満たす全政党）
   - 政党×論点の立場（5段階）と出典URL
   - 政党ごとの解説（「何をしたい？」「何が変わる？」）。全政党で同じ項目・同程度の文字数
   - 政党ごとの公式YouTube動画（全政党で同じ本数）
   - データの基準日（2026年2月衆院選の公約）、対象政党の選定基準
4. **データ検査**
   - 政党データが中立性のルールを満たすかを検査する
   - ルール：全政党が全論点の立場を持つ／すべての立場に出典URLがある／解説の項目が全政党で揃い、文字数の差が許容範囲内／動画の本数が全政党で同じ
5. **結果後のAI対話**
   - LLMで回答文を生成する。材料は政党データ（立場・出典・解説）だけに限る（RAG）
   - 投票先を勧めない。データにないことは「わからない」と答える。回答に出典を付ける
   - キャラの口調（同い年の友達・タメ口・優しい）を保つ
6. **画面**
   - LINE風のトーク画面：左右の吹き出し、既読表示、メッセージが順に届く演出、下部に返信候補ボタンと自由入力欄
   - 配色・ロゴ・スタンプはオリジナル。LINEのブランド要素は使わない
   - 催促やタイマーなど、プレッシャーを与える演出は入れない
   - 結果画面：タイプ、全政党のマッチ率、論点別の内訳、計算方法、AIの解釈一覧（修正可）、データ基準日
   - 政党詳細：解説、出典リンク、公式動画の埋め込み
   - 投票への橋渡し：何歳で投票できるか、次の国政選挙、選挙の仕組みミニ解説
   - シェア画像：論点ごとの自分のスタンスだけ。政党名・マッチ率は載せない

### マッチ率の計算

- 論点ごとに、ユーザーのスタンス（5段階）と政党の立場（5段階）の距離から一致度を出す
- 10論点の単純平均をマッチ率とする。論点の重み付けはしない
- 計算方法を結果画面に明記する

### キャラクター

- 1人。同い年くらいの友達という設定で、タメ口。とても優しい
- 自分の政治的意見は一切言わず、どの回答も肯定的に受け止める聞き役
- アイコンはオリジナルのイラスト。性別ははっきりさせない。名前は政治色のない普通のニックネーム

### 中立性

- 全政党を同じ形式・同じ量で扱う（立場、解説、動画）
- 解説はAIで下書きし、人がチェックしてから事前に用意する。解説をその場で生成しない
- その場で生成するのは結果後のAI対話だけ。材料は事前データに限る

## Testing Decisions

- **よいテストとは**：モジュールの外から見た振る舞いだけを確かめるテスト。内部の関数や状態の持ち方は確かめない。リファクタリングしても壊れないこと
- **テストの境界は2つ**
  1. **診断セッション**：回答解釈器を、決まった値を返す偽物に差し替えて確かめる
     - ボタン回答・自由回答の両方で最後まで進み、最終結果が返ること
     - 既知の回答パターンに対して、期待どおりのマッチ率・一番近い政党・論点別の内訳になること
     - 解釈器が「判断不能」を返したとき「どちらでもない」として扱われ、確認なしで次の設問に進むこと
     - 解釈一覧から回答を修正すると、結果が再計算されること
     - マッチ率の計算はこの境界を通して確かめ、計算関数を個別にはテストしない
  2. **データ検査**：本番の政党データに対して中立性ルールが満たされていることを、CIで毎回確かめる
- **自動テストの対象外**：結果後のAI対話（LLMの出力は毎回変わるため）。代わりに手動チェックリストで確認する
  - 「どこに投票すべき？」に特定の政党を勧めない
  - データにないことを聞くと「わからない」と答える
  - 回答に出典が付く
  - キャラの口調が保たれる
- **Jevの日本語精度**：本実装の段階で、自由回答のサンプル（50文程度）を使って正答率を測る。モック段階では行わない
- **既存のテスト**：リポジトリがまだないため、参考にできる既存テストはない

## Out of Scope

- 地方選挙、個々の候補者、海外の政治
- ログイン、回答の保存、履歴、18歳になったときの通知
- 論点の重み付け（どの論点を重視するかによるマッチ率の調整）
- 公約データの自動抽出（AIによる自動生成のみでの掲載）
- 解説のその場での生成（結果後のAI対話を除く）
- AIがユーザーを問い詰める「詰め」の要素、メンタルゲージ・称号などのゲーム要素
- 複数キャラクター
- ネイティブアプリ（アプリストア配信）
- シェア画像への政党名・マッチ率の掲載

## Further Notes

- **公職選挙法**：18歳未満の選挙運動は禁止されている。選挙期間中に「〇〇党と一致率90%」と投稿すると抵触するおそれがあるため、シェア画像に政党名を載せない
- **個人情報保護法**：政治的な考えは「信条」にあたり、要配慮個人情報になる。対象が未成年でもあるため、回答は保存しない
- **AIの偏り**：2026年2月の衆院選で行われた実験では、LLMが入力されたスタンスや参照できる情報源によって特定の政党を推奨する傾向が報告されている。解説を事前に人がチェックする方針と、AI対話の材料を事前データに限る方針はこのリスクへの対策
- **Jevの制約**：TypeSafe Jevは文章を生成できず、日本語の精度は公式に「英語と同等ではない」とされている。文章が必要な部分（AI対話）はLLMが担う
- **UIの参考**：トーク画面の形はLINE、体験の雰囲気づくりはX（旧Twitter）で話題になった「コンサル詰めシミュレーター」（チャット形式で返信を選ぶUI）を参考にしている。ただしプレッシャーを与える要素は取り入れない
- **役割分担の目安（5人）**：画面／会話の流れとJevの組み込み／結果後のAI対話／政党データ作り／解説文のチェック・キャラ・発表準備
