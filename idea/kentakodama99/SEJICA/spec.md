# 政治家になれる「SEJICA」（仮）仕様

ラベル: `ready-for-agent`

## Problem Statement

中高生は、政治の話題について自分の意見を言葉にし、反対の意見を受け止めた経験がない。学校で意見を求められる場は少なく、反論してくれる相手もいない。そのため、自分の考えがどの政党の考えに近いのかも分からないまま18歳を迎える。

## Solution

AI政治家と議論する一人用の Web アプリ。チームが用意したテーマからランダムに1つ出題し、ユーザーは140字で主張する。性格の違う3人のキャラクターから対戦相手を選ぶと、AI政治家が統計を出典付きで示しながら反論してくる。AI政治家は党に属さない「政治家」という設定で、党ごとの方針は口にせず、一般論で反論する。3ターンのやり取りのあと、結果画面で次の3つを見せる。

- 主張点数（100点）
- 話し方のタイプ
- 全政党との近さ。人が確かめた「党ごと・テーマごとの立場のデータ」をもとに、AI がやり取りの全体から分析する

ログインはなく、書いた文章は保存しない。

## User Stories

### 入口

1. 中高生のユーザーとして、最初に18歳以下かどうかを答えたい。そうすれば対象の年齢のアプリだと分かる
2. 中高生のユーザーとして、ログインせずに始めたい。そうすれば気軽に試せる
3. 中高生のユーザーとして、書いた文章が保存されないと最初に知りたい。そうすれば安心して本音を書ける
4. 中高生のユーザーとして、遊び方を短く知りたい。そうすれば初めてでも迷わない

### テーマと対戦相手

5. 中高生のユーザーとして、テーマをランダムに出してほしい。そうすれば何について話すかを自分で考えなくて済む
6. 中高生のユーザーとして、苦手なテーマが出たら1回だけ引き直したい。そうすれば手が止まらない
7. 中高生のユーザーとして、テーマの短い説明を読みたい。そうすれば知らないテーマでも主張できる
8. 中高生のユーザーとして、対戦相手を3人（やさしい・ふつう・きびしい）から選びたい。そうすれば自分に合った強さで練習できる
9. 中高生のユーザーとして、キャラクターごとの点数の倍率を選ぶ前に知りたい。そうすれば難しい相手に挑む理由が分かる

### 議論

10. 中高生のユーザーとして、テーマについて140字以内で主張したい。そうすれば短くても自分の意見を言える
11. 中高生のユーザーとして、AI政治家から反論を受けたい。そうすれば自分の意見の弱いところに気づける
12. 中高生のユーザーとして、反論の根拠になった統計の出典を見たい。そうすれば反論が本当かどうかを確かめられる
13. 中高生のユーザーとして、反論に再反論したい。そうすれば言われっぱなしで終わらない
14. 中高生のユーザーとして、AI政治家が特定の党の方針を言わないでほしい。そうすれば党ではなく中身で議論できる
15. 中高生のユーザーとして、議論の最後を自分の言葉で終えたい。そうすれば言い負かされた気持ちで終わらない
16. 中高生のユーザーとして、テーマとずれたことを書いたら、AI政治家にキャラクターらしく反応してほしい。そうすれば遊びとして続けられる
17. 中高生のユーザーとして、議論の最中に点数を見せないでほしい。そうすれば点数ではなく議論に集中できる

### 結果

18. 中高生のユーザーとして、主張点数を4項目（根拠・具体性・応答・受け止め）の内訳つきで見たい。そうすれば何を伸ばせばいいかが分かる
19. 中高生のユーザーとして、賛成か反対かで点数が変わらないと知りたい。そうすれば正解の意見を探さずに済む
20. 中高生のユーザーとして、話し方のタイプ（データ派・共感派・反撃派など）を知りたい。そうすれば自分の話し方の特徴が分かる
21. 中高生のユーザーとして、このテーマで自分が全政党とどれくらい近いかを見たい。そうすれば自分の考えと政党を結び付けられる
22. 中高生のユーザーとして、党との近さの根拠（マニフェストの出典）を見たい。そうすれば元の資料を確かめられる
23. 中高生のユーザーとして、3テーマ以上遊んだら「向いている党のタイプ」を知りたい。そうすれば1回の議論だけで決めつけられない
24. 中高生のユーザーとして、自分と各党を2本の軸（変える↔今を保つ、社会で支える↔個人や市場にまかせる）の図で見たい。そうすれば考えの傾向がひと目で分かる
25. 中高生のユーザーとして、議論の途中で自分の考えが動いたことを見たい。そうすれば考えが変わったことを学びとして受け止められる
26. 中高生のユーザーとして、点数・話し方のタイプ・キャラクター名を SNS でシェアしたい。そうすれば友達に挑戦をすすめられる
27. 中高生のユーザーとして、別のテーマでもう一度遊びたい。そうすれば何度も練習できる

### 安全

28. 中高生のユーザーとして、名前や学校名などを書いてしまったら、送る前に止めてほしい。そうすれば個人情報を出さずに済む
29. 中高生のユーザーとして、悪口や差別的な言葉は送れないでほしい。そうすれば遊びの場が荒れない
30. 中高生のユーザーとして、きびしいキャラクターでも人格は否定されないでほしい。そうすれば強い反論でも傷つかずに済む

### 中立性

31. 保護者・教員として、AI政治家が特定の党の方針を口にしないと知りたい。そうすれば誘導を疑わずに済む
32. 保護者・教員として、党との近さが全政党を並べて示されると知りたい。そうすれば特定の党がすすめられていないと分かる
33. 保護者・教員として、党の立場のデータを人が確かめ、出典が付いていると知りたい。そうすれば分析の根拠を信頼できる
34. 保護者・教員として、シェアに党の名前が入らないと知りたい。そうすれば未成年の選挙運動にあたる心配がない

### 運営（チーム）

35. データ担当として、テーマ・テーマの説明・反論に使う統計（出典URL付き）を構造化データで管理したい。そうすればコードを変えずに直せる
36. データ担当として、党ごと・テーマごとの立場（5段階）を AI で下書きし、人が全部確かめてから載せたい。そうすれば AI の誤りや偏りを防げる
37. データ担当として、マニフェストに書いていないテーマを「記載なし」にして、近さの計算から外したい。そうすれば根拠のない判定をしなくて済む
38. データ担当として、データがルールを満たしているかを自動で検査したい。ルールは「全テーマに統計の出典がある」「全党・全テーマの立場が5段階か記載なしになっている」「立場には出典がある」。そうすれば抜けを公開前に防げる
39. データ担当として、党の立場のデータを CC BY のオープンデータとして公開したい。そうすれば UDC でデータを作った貢献を示せる
40. 運営として、1人が1日に遊べる回数を5回までにしたい。そうすれば AI のコストを見積もれる

## Implementation Decisions

### 前提

- ハッカソン提出作品。12/27 提出
- スマホブラウザで動く Web アプリ。ホスティングは Cloudflare
- 一人用。ほかのユーザーとはつながらない
- AI は Claude Haiku 5.5 を Cloudflare Workers から呼ぶ。反論・採点・党のタイプの分析・入力のチェックのすべてに使う
- ログインはしない。匿名の ID と遊んだ記録は端末のブラウザに残す
- 党のデータは第51回衆議院議員総選挙（2026年2月8日投開票）の1回分に固定する。トウタイプ・支持者ワードウルフと共通にする

### ゲームのルール

- 流れ：入口（18歳以下か）→ テーマ出題（1回だけ引き直し可）→ 対戦相手を選ぶ → ① 主張 → ② AI の反論1 → ③ 再反論 → ④ AI の反論2 → ⑤ 再反論 → ⑥ AI のしめの言葉 → 結果
- ユーザーの発言は3回、1回140字まで
- テーマはチームが選んだ8〜10個から。次の3つを満たすものを選ぶ
  - 第51回衆院選のマニフェストで、党ごとに立場が分かれている
  - 中高生の生活に近い
  - 反論に使える統計がある
- テーマとずれた答えにも特別なルールは作らない。AI政治家がキャラクターとして反応し、点数は AI の採点にまかせる

### AI政治家とキャラクター

- 党に属さない「政治家」という設定。党ごとの方針は口にせず、一般論で反論する
- 反論の根拠は、そのテーマ用にチームが用意した統計（e-Stat・白書）からだけ引き、出典を示す。国会会議録とマニフェストは、反論には使わない
- しめの言葉では勝ち負けをつけない
- キャラクターは3人。名前と見た目は UI 担当が決める

| キャラクター | 言い方 | 反論の鋭さ | 点数の倍率 |
|---|---|---|---|
| やさしい | ていねい | 1つの論点をやさしく | ×1.0 |
| ふつう | ふつう | 論点をはっきり | ×1.2 |
| きびしい | 強め（人格は否定しない） | 弱いところをつく | ×1.5 |

### 採点

- 議論が終わったあとに1回だけ採点する。議論の最中は点数を見せない
- 4項目×25点＝100点に、キャラクターの倍率をかける

| 項目 | 見ること |
|---|---|
| 根拠 | 理由や事実を挙げたか |
| 具体性 | 例や数字を使ったか |
| 応答 | AI の反論に、正面から答えたか |
| 受け止め | 反対の意見の良い点を認めたか |

- 賛成か反対かでは点数が変わらない。採点の表（ルーブリック）にこのことを書く
- 話し方のタイプは4項目の点数から出す（例：データ派＝根拠と具体性が高い、共感派＝受け止めが高い、反撃派＝応答が高い）

### 党のタイプと傾向分析

- やり取りの全体から、AI がそのテーマへの立場を分析する。分析の材料は、人が確かめた「党ごと・テーマごとの立場のデータ」だけ。AI が自分の知識で持っている各党のイメージは使わない
- 結果では、1つの党を言い切らない。全政党との近さを並べ、それぞれにマニフェストの出典を付ける
- 1回遊ぶごとに「このテーマで近い党」を出し、3テーマ以上遊んだら「向いている党のタイプ」を出す
- 議論の途中で立場が動いたら、その変化も見せる（例：賛成 → どちらかといえば賛成）
- 考えの傾向は、2本の軸の図にあなたと各党を置いて見せる
  - 変える ↔ 今を保つ
  - 社会で支える ↔ 個人や市場にまかせる
- 「記載なし」の党は、そのテーマの近さの計算から外す

### 安全

- 入口で18歳以下かをたずねる
- 書いた文章はサーバーに保存しない。保存するのは点数・立場の判定・話し方のタイプだけ
- 個人情報（名前・学校名・電話番号など）や悪口・差別的な言葉は、反論を作る前に AI で見つけて止め、書き直してもらう
- 1日5回の上限はサーバー側で数える。数えるのは、匿名の ID と接続元の IP の組み合わせ
- シェアできるのは点数・話し方のタイプ・キャラクター名だけ。党の名前と近さは出さない

### モジュール

1. **議論の進行**（メインのモジュール）
   - テーマの出題と引き直し、キャラクターの選択、ターンの切り替え、140字の制限、結果への移動を受け持つ状態機械
   - 乱数を外から渡せるようにし、テストで固定できるようにする
2. **AI政治家**
   - テーマ・キャラクター・それまでのやり取り・使ってよい統計を受け取り、反論やしめの言葉を返す。返した反論が、どの統計を使ったかも返す
3. **採点と分析**
   - やり取りの全体と党の立場のデータを受け取り、4項目の点数・話し方のタイプ・立場とその変化・全政党との近さを返す
   - 倍率をかけた合計点や、話し方のタイプの決め方など、計算で決まる部分は AI に任せずコードで計算する
4. **入力のチェック**
   - 個人情報や悪口・差別的な言葉を見つけ、送る前に止める
5. **利用回数の上限**
   - 匿名の ID と IP の組み合わせで、1日5回までを数える
6. **データ**
   - テーマ・テーマの説明・統計（出典URL付き）・党ごと・テーマごとの立場（5段階か記載なし、出典付き）・2本の軸の上での各党の位置。リポジトリ内の静的データ
   - データ検査（全テーマに統計の出典があるか、全党・全テーマの立場がそろっているか、立場に出典があるか）
7. **記録**
   - 端末のブラウザに匿名の ID と遊んだ記録を残し、遊んだテーマの数を数える

## Testing Decisions

- **よいテストとは**：モジュールの外から見た振る舞いだけを確かめるテスト。内部の状態の持ち方は確かめない
- **議論の進行**：乱数を固定して、次のことを確かめる
  - 引き直しは1回だけできること
  - ユーザーの発言は3回、AI の反論は2回で結果へ進むこと
  - 141字以上は送れないこと
- **採点と分析**：計算で決まる部分を確かめる
  - 倍率をかけた合計点
  - 4項目の点数から話し方のタイプが決まること
  - 「記載なし」の党が近さの計算から外れること
  - 3テーマ未満では「向いている党のタイプ」を出さないこと
- **利用回数の上限**：6回目が断られること、日付が変わると数え直すこと
- **データ検査**：本番のデータに対して、CI で毎回確かめる
- **AI の出力**：自動テストの対象外。中立性（党ごとの方針を言わない、賛成か反対かで点が変わらない）は、テーマごとに賛成側と反対側の答えを用意して手で確かめる

## Out of Scope

- ログイン、端末をまたいだ記録の引き継ぎ
- ほかのユーザーとの対戦、ランキング
- 声での入力
- ユーザーが自由にテーマを入力すること
- AI政治家が特定の党の議員として話すこと
- 反論に国会会議録やマニフェストを使うこと
- 第51回衆院選以外の選挙、地方議会

## Further Notes

- **公職選挙法**：18歳未満の選挙運動は禁止されている。党の名前と近さはシェアに入れない。結果画面では、党との近さは参考であり、投票先をすすめるものではないことを明示する
- **データの作り方**：党の立場は AI で下書きし、人が全部確かめる（ミライの選択の ADR 0002 と同じ方針）
- **ほかの案との関係**：トウタイプ（選択式で党のタイプを診断）・支持者ワードウルフ（党どうしの違いを見抜く）と、党のデータを共通にする。SEJICA の役割は「意見を言葉にして、反論を受け止める」練習
- **オープンデータ**：e-Stat と白書の利用規約、マニフェストを構造化データにして公開してよいかは要確認
