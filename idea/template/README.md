# アプリ案テンプレート

アプリ案を出すときは、**このテンプレートの項目をすべて埋める**こと。
各自 `idea/<名前>/<アイデアの英字名>/README.md` に1案ずつ書く（例：`idea/akimoto/mogi-senkyo/README.md`）。

---

## モックの格納先・作り方

**モックの置き場所：案のフォルダの中の `mock/`**（例：`idea/akimoto/mogi-senkyo/mock/index.html`）

> ※モックは、HTML・CSS・JavaScriptは**ファイル分け**、htmlファイルでcss・javascriptを**参照**するようにしてください（**保守性の観点で**）。

```
mock/
├── index.html      ← css/js は <link> と <script src> で参照
├── style.css
└── script.js
```

## 各項目の書き方

| 項目 | 書くこと |
|---|---|
| **アイデア名** | アプリ名。愛称があれば「」で添える |
| **解決する課題** | 未成年の政治参画のどの課題か（例：政治が身近でない、意見を出す場がない、選挙のしくみを知らない） |
| **既存プロダクトの有無** | 同じことをやっている既存サービス・既存施策があるか。**焼き増しを避けるため必ず調べる** |
| **ペルソナ** | `●●で困っている●●へ` — 誰の、どの困りごとか |
| **キャッチコピー** | その未来を、ひとことで |
| **アプリ概要（30秒でいうと）** | `●●をXXXすることが可能` — 30秒で言い切れる長さに |
| **その他アプリ機能** | 主要機能を列挙（例：検索機能、マッチング機能） |
| **使うオープンデータ** | どのデータを、どこから（URL）。利用規約も確かめる。UDC はオープンデータの活用を見るコンテスト |
| **未成年向けだから成立する理由** | 選挙権を持つ大人向けのサービスではなく、未成年向けである必然性 |
| **課題との紐づき** | `XXXに対して、●●の機能で解決できる` — 課題と機能を1対1で結ぶ |
| **期待効果** | 解決することによる課題解決、ひいてはコストXXX円削減 |
| **画面イメージ（あれば）** | モックへのリンク、または画面のスケッチ |

> 「既存プロダクトの有無」は、既存の政治・選挙情報サービス、主権者教育の教材、模擬選挙の取り組みと比べる。調べたものは [`survey/README.md`](../../survey/README.md) にためる。

### 応募資料の項目との対応

作品本応募の資料に書く項目の例。本応募フォームの項目が分かったら合わせて直す。

| 応募資料の項目 | テンプレートの項目 |
|---|---|
| アイデア名 | アイデア名 |
| 目的（背景・課題） | 解決する課題、課題との紐づき |
| 対象利用者 | ペルソナ |
| 期待効果 | 期待効果 |
| 実現するためのアイデア（ソリューションイメージや構成図） | アプリ概要、その他アプリ機能、画面イメージ |
