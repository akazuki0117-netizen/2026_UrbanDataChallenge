# 公開のルール（このリポジトリは public）

このリポジトリは**誰でも見られる**。push したものは、あとで消してもコピーやキャッシュが残ると考える。
push の前に、[`skills/dev/public-check/`](../skills/dev/public-check/SKILL.md) のチェックを必ず通す。

## 載せないもの

| 載せないもの | 例 | かわりにどうするか |
|---|---|---|
| **実名** | メンバーの名字・名前、議事録に出てくる候補の方の名前 | メンバーは **GitHub のユーザー名**で書く（下の表）。メンバー以外は「バックエンドの候補の方」のように役割で書く |
| **連絡先** | メールアドレス、電話番号、LINE の ID、住所 | 書かない。連絡は LINE グループで |
| **所属の内部情報** | 会社名・部署、社内のコンテスト・制度、本業の仕事の中身 | 書かない。「本業の都合で〇日は動けない」程度にとどめる |
| **個人の事情** | 資格試験、外部の案件、健康、家族のこと | 書かない（予定に要るなら「動けない日」だけ） |
| **秘密の値** | API キー、トークン、パスワード、`.env` の中身、秘密鍵 | `.env`（`.gitignore` 済み）に入れる。リポジトリには `.env.example`（変数名と説明だけ）を置く |
| **公開してよいか分からないデータ** | 利用規約で再配布が禁止のデータ、提供元が限定公開の資料 | 出典の URL と取得日だけ書く。本体は入れない |
| 会議の録画・文字起こしの原本 | Google Meet の自動メモ・録画 | 議事録（要約）だけを `meeting/` に置く |

## コミットの作者のメールアドレス

コミットには作者の名前とメールアドレスが残り、public だと誰でも見られる。**このリポジトリでは GitHub の noreply アドレスを使う。**

```bash
git config user.name "<GitHub のユーザー名>"
git config user.email "<数字のID>+<GitHub のユーザー名>@users.noreply.github.com"
```

- 数字の ID は GitHub の Settings → Emails の「Keep my email addresses private」の下に出ている
- 同じ画面の「Block command line pushes that expose my email」をオンにすると、うっかり本物のアドレスで push するのを GitHub が止めてくれる

## 載せてしまったら

1. すぐに LINE グループで知らせる（直す人が重ならないように）
2. API キー・トークンは、**消す前にまず無効にする**（発行元で取り消して作り直す）。履歴から消しても、見られた可能性は消えない
3. ファイルから消すコミットを push する。履歴からも消す必要があるかは、akazuki0117-netizen が判断する
