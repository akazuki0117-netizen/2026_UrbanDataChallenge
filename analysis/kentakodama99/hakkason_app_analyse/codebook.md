# コードブック（分類基準）

作成日：2026-11-21。対象：東京都「都知事杯オープンデータ・ハッカソン」2026 年度 提出作品 486 件。

## 0. 付与の方法

- **一次コーディング（全 486 件）**：このコードブックをそのままキーワード規則にした [`scripts/phase4_features.py`](scripts/phase4_features.py) で機械的に付与する。人の気分で基準がぶれないようにするため。正確なキーワード（正規表現）はスクリプトが正本。
- **判定に使う材料**：タイトル＋「サービス内容」（原文）＋「利用データ」欄の URL ＋提出物の有無。メンバー氏名は使わない（人数のみ）。
- **規則を変えたら全件を付け直す**（スクリプトを再実行。部分更新はしない）。
- **二重コーディング**：ファイナリスト 24 件＋対照群 24 件について、分析者が本文を読んで独立に付けたもの（`data/manual_coding.csv`）と機械付与の一致率を出す（レポートに記載）。
- **`uncertain` の扱い**：機械付与は必ず値が入る。読み取りで判断が割れたものは `manual_coding.csv` の `uncertain` 列に理由を書く。

### 前提として知っておくこと

「サービス内容」は全作品がほぼ同じ体裁（約 250〜400 字。「〜するサービス。〜という課題に対応。〜する。〜で構築し、〜（AI）を活用した。」）になっている。**主催者側で整形・要約された文章**とみられる。したがって「説明文の書き方・構成」の差はチームの実力差をあまり反映しない。一方「何が書かれているか（数字・対象者・データ・技術）」は元の提出内容を反映するので特徴量として使う。

## 2. 想定ユーザー（`users`、`user_specific`、`user_gov`、`user_business`）

| 値 | 基準 |
|---|---|
| 高齢者／障害者／外国人／子育て世帯／子ども・学生 | その属性の語が本文にある → `user_specific=1`（特定の困りごとを持つ人） |
| 行政職員 | 職員、庁内、自治体が／向け、政策立案、養護教諭、救急隊 など → `user_gov=1` |
| 事業者 | 事業者、店舗、企業、運営者、農家 など → `user_business=1` |
| 都民一般 | 上のどれにも当たらない |

## 3. 課題の具体性（`problem_specificity` 1〜3）

「誰の・どんな場面の・どんな困りごと」が書かれているか。

| 値 | 基準 |
|---|---|
| 3（具体的） | 課題を示す言い回し（「〜という課題に対応」「〜に着目」等）があり、**かつ** 課題の説明までに数字の根拠（%・人・件・時間 など）があり、**かつ** 特定の対象者（§2 のどれか）が書かれている |
| 2（中程度） | 課題の言い回しがあり、数字の根拠 **または** 特定の対象者のどちらかがある |
| 1（抽象的） | それ以外（課題の言い回しが無い、または対象も数字も無い） |

補助：`problem_number`（課題の説明に数字があるか）、`first_person_origin`（実体験・聞き取り・現場の声 への言及）。

## 5. 使用データ

| 列 | 基準 |
|---|---|
| `n_data_total` | 「利用したオープンデータ」欄の項目数 |
| `n_data_tokyo_catalog` | うち東京都オープンデータカタログ（`catalog.data.metro.tokyo.lg.jp` 等）の URL 数 |
| `n_data_tokyo_any` | うち `metro.tokyo` ドメイン全体（都の統計サイト等も含む）の URL 数 |
| `n_data_external` | それ以外（国・民間・OSM 等）の URL 数 |
| `data_cross` | 都のデータと都以外のデータを両方使っている |
| `data_no_tokyo` | 都のデータ URL が 1 つも無い |
| `data_national` / `data_osm_private` | 国（go.jp、e-Stat、PLATEAU 等）／OSM・民間（OpenStreetMap、Mapillary、ODPT、Google 等）の URL がある |

## 6. データの使い方（`data_use_level` 1〜3）

| 値 | 基準 |
|---|---|
| 3（結合して新しい指標・推定を作る） | 本文に 掛け合わせ、組み合わせ、重ね、統合、独自、スコア、指数・指標、推定、算出、予測、最適、試算、シミュレーション のいずれか |
| 2（加工・集計） | 3 に当たらず、集計、解析、分析、変換、構造化、抽出、分類、言語化、可視化 のいずれか |
| 1（表示するだけ） | どちらも無い |

補助：`desc_big_number`（扱ったデータ量を示す大きな数字。例「588,220 地点」）。

## 7. 技術

| 列 | 基準 |
|---|---|
| `ai_any` | 生成 AI・LLM・各種 AI ツール名への言及がある |
| `ai_in_product` | AI が **利用者の使う機能として** 動いている（「AI が説明」「Vision AI で解析」「LLM」「RAG」「MCP」等） |

## 11. モック確認（Phase 3、対象 48 件）

| 項目 | 値 |
|---|---|
| `status` | 動く／一部動く／リンク切れ・エラー／ログイン必須／資料・動画のみ／デモ URL なし |
